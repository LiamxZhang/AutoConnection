# 便携式工作网络连接工具设计规格

日期：2026-07-23

## 1. 背景

现有 `lab_net_login_no_requests.py` 通过工作网络门户 `1.1.1.3` 登录，并用 Microsoft 网络探测地址验证公网连接。用户目前需要手工设置环境变量并重复运行命令。新软件将这套能力包装成简洁的桌面 UI，并支持每天固定时间自动联网。

现有《上网脚本使用命令》包含明文真实凭据。该文件不得进入版本历史；实现阶段必须移除其中的凭据，用户应更换已暴露的密码。

## 2. 目标与非目标

### 目标

- 用同一套 Python 源码分别生成 Windows x64 与 Linux x86_64 的免安装单文件程序。
- 提供中文、English 和跟随系统三种界面语言设置。
- 安全保存工作网络账号和密码。
- 仅提供“联网”和“每日定时联网”两项基础功能。
- 登录失败且检测到活动 VPN/隧道网卡时，显示明确的 VPN 原因提示。
- 主窗口关闭后驻留系统托盘；托盘不可用时安全退化为普通最小化。
- 用 Git 与私有 GitHub 仓库管理源码和版本，并通过 GitHub Actions 构建两个平台的发布文件。

### 非目标

- 不注册系统服务，不创建开机启动项，不写入系统级安装目录。
- 不在程序完全退出时执行定时任务。
- 不支持 macOS、移动系统或无图形界面的服务器。
- 不提供多账号、多门户、多条定时规则、流量统计或网络配置管理。
- 不保证能证明 VPN 是登录失败的唯一原因，只提供基于活动隧道接口的高可信提示。

## 3. 支持范围与发布形式

- Windows：Windows 10/11 x64，发布单文件 `.exe`。
- Linux：Ubuntu 22.04+ 或使用兼容 glibc 的主流 x86_64 桌面发行版，发布单文件可执行程序。
- 源码运行时采用 Python 3.12。
- UI 采用 Tkinter/ttk，发布采用 PyInstaller `--onefile`。
- `keyring`、`pystray`、Pillow 和 `psutil` 作为运行依赖打包进可执行文件，不要求用户单独安装。
- 最终用户无需安装 Python。程序首次运行会在当前用户的配置目录生成一个非敏感 JSON 设置文件；密码不写入该文件。

Linux 的桌面托盘没有统一标准。首版通过 `pystray` 使用可用的桌面后端；若后端初始化失败，关闭窗口改为最小化到任务栏，应用继续运行并明确提示退化状态。

## 4. 架构

系统分为四个边界清晰的部分：

1. UI 与托盘：展示状态、接收操作、管理设置窗口和托盘菜单。
2. 应用控制与调度：串联登录流程、后台任务、状态转换、每日触发和本地化刷新。
3. 网络与诊断：门户登录、联网探测、VPN 接口识别和错误分类。
4. 存储：JSON 非敏感设置及操作系统凭据库。

网络操作不得在 Tk 主线程执行。手动联网和定时联网必须调用同一个应用服务入口，以保证行为与错误处理一致。UI 只能通过线程安全的消息队列或 Tk `after` 回调接收后台结果。

建议源码边界如下；源代码文件数量不影响最终单文件发布物：

- `src/net_connector/app.py`：入口、窗口、托盘和 UI 状态绑定。
- `src/net_connector/network.py`：HTTP、RC4、联网探测与门户登录。
- `src/net_connector/scheduler.py`：每日触发计算与补执行规则。
- `src/net_connector/storage.py`：设置和系统凭据库。
- `src/net_connector/vpn.py`：跨平台接口枚举与 VPN 启发式判断。
- `src/net_connector/i18n.py`：中英文文本及系统语言解析。

## 5. 用户界面

### 主窗口

- 窗口约 420 x 390，保持紧凑并允许系统字体差异带来的最小扩展。
- 顶部显示“工作网络”，右侧使用方形齿轮图标打开设置；图标带悬停提示和可访问名称，不显示“设置”文字。
- 状态区域显示状态圆点、当前状态和上次检查时间。
- “联网”是居中、约 160 像素宽的主要按钮，不占满窗口。
- 每日定时区域包含启用开关、只接受有效 `HH:MM` 的时间输入、“每天”说明和下次执行时间。
- 底部说明关闭窗口后驻留托盘；托盘退化时改为相应提示。

### 设置窗口

- 包含账号、密码和界面语言。
- 密码默认掩码，允许临时显示。
- 界面语言使用只读下拉菜单，选项固定为“跟随系统 / 中文 / English”。
- 语言选择后立即预览，保存后持久化；取消则恢复打开窗口前的语言设置。
- 保存凭据失败时设置窗口保持打开并显示原因。

### 托盘菜单

- 显示主窗口。
- 立即联网。
- 退出。

## 6. 联网流程

一次联网操作按以下顺序执行：

1. 阻止并发重复请求，并将 UI 切换为“正在检查”。
2. 从系统凭据库读取账号和密码；缺失时打开或引导进入设置。
3. 请求联网探测地址。若已经在线，返回“已联网”，不访问门户。
4. 直接访问门户登录页进行预热。门户请求不使用系统 HTTP 代理，以免代理设置误导内部门户访问。
5. 使用毫秒时间戳作为 `auth_tag`，按现有 RC4 兼容算法加密密码并提交登录接口。
6. 等待短暂网络切换后再次探测公网。
7. 成功则更新状态与时间；失败则进入错误分类和 VPN 诊断。

敏感值不得写入控制台、日志、异常详情、遥测或 GitHub Actions 输出。首版不创建持久日志文件，以减少文件数量和泄露面。

## 7. 每日调度

- 用户只能配置一个本地时间，每天重复一次。
- 定时功能启用后，调度器记录下一次绝对触发时间，并使用 Tk 的短周期回调检查，不使用阻塞式 `sleep`。
- 应用持续运行时，到达或超过目标时间且当天尚未执行，就调用与手动联网相同的服务入口。
- 电脑睡眠导致错过目标时间时，恢复运行后的首次检查补执行一次。
- 应用完全退出期间不会触发；之后重新启动也不追补上一次运行会话之前错过的任务，而是计算下一个未来时间。
- 修改时间、启用或停用后立即重新计算并显示下次执行时间。
- 单次定时登录失败后不自动循环重试，避免错误凭据或 VPN 状态导致频繁请求；用户可手动重试，下一自然日仍按计划执行。

## 8. 凭据与设置

- Windows 使用 Windows Credential Manager；Linux 使用 Secret Service/keyring。
- 凭据服务名固定为 `portable-network-connector`，使用固定记录键保存包含账号和密码的凭据对象，避免必须先从明文设置中读取账号才能检索密码。
- JSON 设置只包含版本、语言模式、定时启用状态和每日时间。
- Windows 设置路径为 `%APPDATA%\PortableNetworkConnector\settings.json`；Linux 设置路径为 `${XDG_CONFIG_HOME:-~/.config}/portable-network-connector/settings.json`。
- 设置文件采用原子替换写入，损坏时回退到默认设置并提示用户。
- 系统凭据库不可用时不允许明文降级；界面说明需要启用相应系统凭据服务。
- 将程序复制到另一台电脑不会复制凭据，用户需要重新输入账号密码。

## 9. VPN 诊断与错误模型

VPN 检测枚举活动网络接口，并对接口名称、描述和常见类型做大小写不敏感匹配，包括 `tun`、`tap`、`wireguard`、`wg`、`ppp`、`vpn` 及常见厂商标识。只有登录或联网验证失败时才把 VPN 结果提升为用户错误原因。

用户可见错误至少分为：

- 未配置账号或密码。
- 系统凭据库不可用或保存失败。
- 门户不可达或请求超时。
- 登录被门户拒绝或返回异常响应。
- 登录请求完成但公网验证仍失败。
- 检测到活动 VPN，可能阻断工作网络门户；建议断开后重试。
- 未知内部错误，提供不含敏感信息的简短描述。

若检测到 VPN，错误消息必须使用“可能导致”而非断言 VPN 是唯一原因。

## 10. 本地化

- 所有用户可见字符串使用稳定消息键，不在业务逻辑中散落中文或英文。
- “跟随系统”解析本机区域设置；中文区域使用中文，其他区域使用 English。
- 切换语言会刷新主窗口、设置窗口、托盘菜单、状态文本、对话框和时间说明。
- 动态错误通过错误代码和参数本地化，不直接翻译底层异常字符串。

## 11. 测试与构建

使用 `pytest`，通过依赖注入或 mock 隔离网络、时钟、接口枚举和凭据库。测试至少覆盖：

- RC4 兼容算法的固定测试向量和空密码防护。
- 已联网时不提交登录；离线时的成功、超时、门户拒绝和验证失败。
- 请求体字段正确且测试输出不包含密码。
- VPN 接口识别的阳性、阴性和大小写情况。
- 每日下一次时间计算、午夜跨日、睡眠补执行、同日防重复及重启不追补。
- 设置默认值、校验、原子保存、损坏恢复和凭据库失败。
- 中英文消息完整性、系统语言解析和动态切换。
- UI 的最小启动与后台结果回传冒烟测试。

GitHub Actions 在 Windows 和 Ubuntu runner 上运行测试并分别执行 PyInstaller 构建。发布工作流在版本标签上生成两个清晰命名的构建物，并附带 SHA-256 校验值。

## 12. GitHub 与版本安全

- 当前目录初始化为 Git 仓库，默认分支使用 `main`。
- 远程仓库默认命名 `portable-network-connector`，初始设为私有；若当前 GitHub 账号已存在同名仓库，上传前由用户指定新名称。
- `.superpowers/`、构建目录、缓存、虚拟环境和 PyInstaller 中间文件不进入版本库。
- 提交或推送前运行凭据字符串扫描；包含真实账号或密码的旧说明必须先清理。
- 首个可用版本使用语义化版本 `v0.1.0`。
- 创建远程仓库和推送需要用户已授权的 GitHub 会话；若当前机器没有可用授权，完成本地提交和构建后再请求登录。

## 13. 验收标准

满足以下条件才视为首版完成：

1. Windows 10/11 x64 和目标 Linux 桌面无需预装 Python即可直接启动对应单文件程序。
2. 用户可以安全保存账号密码，并可在中英文之间切换。
3. 手动联网在已在线、成功登录和各类失败场景下给出正确状态。
4. 一个每日时间可启用、修改、保存，并在应用或托盘运行时每天触发一次。
5. 登录失败且存在活动 VPN 接口时显示已批准的 VPN 提示语义。
6. 关闭主窗口后托盘行为正确，Linux 托盘不可用时不会使应用失联。
7. 源码和测试中不存在真实凭据，自动测试通过，两个平台的构建工作流有效。
8. 本地 Git 历史清洁，并推送到私有 GitHub 仓库。
